# 项目实现方案

> 基于 ShowUI-2B 的 GUI Agent 定位与导航系统 | ScreenSpot 76.7%（超越论文 75.1%）

---

## 1. 项目背景

### 1.1 项目目标

构建一个能够根据自然语言指令在 GUI 截图上定位目标元素的定位系统（Grounding System），使智能体能够理解"点击搜索按钮"、"输入用户名"等指令，并输出精确的点击坐标。

### 1.2 要解决的问题

现有的通用大模型（如 GPT-4V、Qwen-VL）虽然在许多视觉任务上表现优异，但在细粒度 GUI 元素定位上存在两个核心问题：

- **精度不足**：通用模型在 ScreenSpot 等 GUI 基准上的定位准确率（~54%）远低于专用模型（如 ShowUI 的 75.1%）
- **成本过高**：每次定位调用远程 API 大模型，延迟约 12s/次，无法满足实时交互需求

### 1.3 核心思路

放弃通用 API 大模型方案，改用**专为 GUI 定位设计的 VLM**：

- 使用 **ShowUI-2B** 作为定位模型，基于 Qwen2-VL-2B 在 GUI 数据上微调
- 无需训练，直接从 HuggingFace 加载预训练权重
- 截图 + 指令 → 直接输出归一化坐标 `[x, y]`

**关键收益：**

| 对比项 | 通用 API 大模型 | ShowUI-2B |
|:------|:--------------:|:---------:|
| ScreenSpot 准确率 | 54.4% | **72.5%** |
| 推理速度 | 12.33s/样本 | **0.75s/样本** |
| 是否需要训练 | 否 | 否 |
| 是否需要 API 调用 | 是（远程） | **否（本地）** |
| 成本 | 按 token 付费 | 免费 |

## 2. 总体架构

### 2.1 系统层级

```
+-----------------------------------------------------------+
|                     Agent Layer                            |
|  AgentRunner / LLMGroundedPolicy / BasePolicy              |
|  （决策循环、历史记忆、动作执行）                            |
+-----------------------------------------------------------+
|                   Grounding Layer                          |
|  ShowUIGrounder (implements BaseGrounder)                  |
|  输入：截图 + 指令 → 输出：归一化坐标 [x, y]              |
+-----------------------------------------------------------+
|                   Model Layer                              |
|  ShowUI-2B (Qwen2-VL-2B, 预训练权重, 无需训练)            |
|  截图 + 指令 → Qwen2-VL 编码器 → 解码器 → 坐标文本        |
+-----------------------------------------------------------+
|                   Environment Layer                        |
|  SeleniumWebEnv / MiniWoBEnv / MockWebEnv                  |
|  （提供截图、DOM 元素、动作执行）                            |
+-----------------------------------------------------------+
```

### 2.2 两种运行模式

| 模式 | 说明 | 适用场景 |
|:----|:-----|:---------|
| **评测模式** | 在 ScreenSpot 测试集上计算 Point Accuracy | 性能评估 |
| **推理模式** | 集成到 Agent 循环中，实时定位 GUI 元素 | 实际运行 |

### 2.3 数据流

```
推理阶段：
  用户指令 "search button" + 截图
       |
       v
  ShowUI-2B 处理器（processor.apply_chat_template）
       |
       v
  ShowUI-2B 模型（Qwen2VLForConditionalGeneration.generate）
       |
       v
  输出文本 "[0.73, 0.21]"
       |
       v
  ast.literal_eval 解析 → [0.73, 0.21]
       |
       v
  GroundingResult(point=[0.73, 0.21], score=1.0)
       |
       v
  返回给 Agent 循环执行点击
```

## 4. 模型结构

### 4.1 ShowUI-2B 架构

```
ShowUI-2B = Qwen2-VL-2B-Instruct + GUI 数据微调

输入截图 (任意分辨率)              输入指令 ("search button")
       |                                     |
       v                                     v
Qwen2-VL ViT (14x14 patches)        Qwen2-VL Tokenizer
       |                                     |
       v                                     v
视觉特征序列                    文本 token 序列
       |                                     |
       +----------- Qwen2-VL LLM ------------+
                   (28层, 1536 hidden)
                       |
                       v
               坐标文本 "[0.73, 0.21]"
```

### 4.2 关键设计

- **视觉编码器**：Qwen2-VL 自带的 ViT，patch size 14，支持动态分辨率
- **语言模型**：Qwen2-VL-2B 的 28 层 Transformer decoder
- **视觉-文本融合**：Qwen2-VL 原生的交叉注意力机制
- **输出格式**：直接生成坐标文本，通过 `ast.literal_eval` 解析为 `[x, y]` 列表

### 4.3 模型参数

| 模块 | 参数量 |
|:----|:------:|
| Qwen2-VL ViT | ~0.6B |
| Qwen2-VL LLM | ~1.4B |
| **总计** | **~2B** |

## 6. 核心接口设计

### 6.1 Grounder 接口

```python
class ShowUIGrounder(BaseGrounder):
    """基于 ShowUI-2B 的 GUI 定位器。"""

    def __init__(
        self,
        model_name: str = "showlab/ShowUI-2B",
        device: str = "cuda",
        confidence_threshold: float = 0.0,
        max_new_tokens: int = 128,
    ):
        ...

    def predict(
        self,
        screenshot_path: str,
        query: str,
        elements: list[UIElement] | None = None,
        dom_text: str | None = None,
    ) -> GroundingResult:
        """定位指定元素。

        Args:
            screenshot_path: 截图文件路径
            query: 指令文本，如 "search button"
            elements: 可选 DOM 元素列表（暂未使用）
            dom_text: 可选 DOM 文本（暂未使用）
        Returns:
            GroundingResult: 包含归一化坐标 (point)、置信度 (score) 等
        """
```

### 6.2 调用流程

```python
# 实例化
grounder = ShowUIGrounder()

# 单次定位
result = grounder.predict(
    screenshot_path="screenshot.png",
    query="search button",
)
# result.point = [0.73, 0.21]
# result.score = 1.0

# 集成到 Agent
policy = LLMGroundedPolicy(
    grounder=keyword_grounder,       # DOM 文本兜底
    model=vlm_model,                 # 决策用
    use_vision=True,
    visual_grounder=grounder,        # 视觉定位用 ShowUIGrounder
)
```

## 7. 推理流程

### 7.1 单次推理步骤

```
输入：截图路径 + 指令文本
   |
   1. 构建消息列表（system prompt + image + text）
   2. processor.apply_chat_template → 文本
   3. processor(images, text) → pixel_values, input_ids
   4. model.generate() → 输出 token ids
   5. processor.batch_decode → 文本 "[0.73, 0.21]"
   6. ast.literal_eval → [0.73, 0.21]
   |
输出：GroundingResult(point=[0.73, 0.21], score=1.0, ...)
```

### 7.2 推理性能

| 指标 | 值 |

| 单次推理延迟（RTX 3090） | ~0.75s |
| 峰值显存占用 | ~4GB |
| 模型加载时间 | ~2s |
| 支持批量推理 | 否（VLM 逐条生成） |

## 11. 第二阶段：超越 ShowUI-2B

当前基线：ScreenSpot **76.7%**（已超越论文 75.1%）。下一阶段目标：**突破 80%**。

### 11.1 DOM-ShowUI 坐标融合（最高优先级）

ShowUI 输出坐标后，与 Selenium 提取的 DOM 元素位置做交叉验证：

```
ShowUI 输出坐标 [0.5, 0.3]
       │
       ▼
遍历所有 DOM 元素，查找包含该坐标的元素
       │
       ├─ 找到匹配元素 → 取 DOM 元素中心坐标（更精确）
       │
       └─ 未找到 → 保持 ShowUI 坐标
```

**预期收益**：+3-5%，因为 DOM 坐标是精确的，ShowUI 有时会落在元素边缘。

### 11.2 OCR 辅助定位（高优先级）

对 text 类型元素，ShowUI 目前 82.6%。用 OCR 做二次确认：

```
ShowUI 输出坐标 [x, y]
       │
       ▼
在坐标附近区域运行 OCR，提取文字
       │
       ▼
OCR 文字 vs 指令文字 → 匹配则确认，不匹配则调整
```

**预期收益**：+2-3%，特别对 text 类型。

### 11.3 Navigation 模式集成

ShowUI 支持直接输出 `{'action': 'CLICK', 'position': [x, y]}`，无需外部 VLM 决策。

将 `LLMGroundedPolicy` 中的 `_resolve_position` 方法扩展为：当 visual_grounder 是 ShowUIGrounder 时，调用 `predict_action()` 而非 `predict()`。

### 11.4 推理加速

| 优化项 | 预期收益 | 难度 |
|:------|:--------|:----|
| torch.compile 编译 | 1.2x | 低 |
| KV cache 复用（同图多次定位） | 2x | 中 |
| 模型量化 (bfloat16 → int8) | 1.5x | 中 |
| **Token Selection 实现** | **1.5x** | 高 |

### 11.5 数据收集与 LoRA 微调

当积累到 5000+ 条真实场景数据后，用 LoRA 微调 ShowUI-2B：

- 基础模型：`showlab/ShowUI-2B`
- LoRA rank: 64, alpha: 128
- 学习率: 1e-4
- 训练数据：真实场景截图 + 标注
- 预期收益：+5-10%

### 11.6 阶段目标

| 阶段 | 措施 | 目标准确率 |
|:----|:-----|:----------:|
| 当前 | 基线 | 76.7% |
| 短期 | DOM 融合 + OCR 辅助 | 80%+ |
| 中期 | Navigation 集成 + 推理加速 | 80%+（0.3s/样本） |
| 长期 | LoRA 微调 | 85%+ |

### 12.2 失败案例总结

#### 12.2.1 错误类型分布

```
错误类型分布（296 个失败样本）：

ICON_CONFUSION (图标混淆)    █████████████████████ 122 (41.2%)

```

#### 12.2.2 逐错误类型分析

**1. ICON_CONFUSION（122 个，占 41.2%）— 核心问题**

这是最大的错误来源，模型对图标类元素的定位准确率仅 66.1%（Text 为 85.5%）。

典型失败案例：
- "add a new one" → 预测到页面右上角而非 + 按钮
- "fork the a11y project" → 预测到附近而非 fork 图标
- "full screen display" → 预测到页面中央而非全屏图标
- "thumb up" → 预测到错误位置

高发平台：android（22）、macos（20）、ios（19）、tool（18）

**根因分析**：
1. 图标缺乏语义文本，模型只能依赖视觉特征区分
2. 不同平台的相似图标视觉差异小（如"更多选项"三个点）
3. 小图标（<30px）在低分辨率下特征模糊
4. ShowUI 训练数据中图标类样本可能不足或质量不均

**2. TEXT_ERROR（65 个，占 22.0%）**

文本元素的定位错误，主要集中在论坛（forum）和工具（tool）类页面。

典型失败案例：
- "check followers" → 预测到完全错误位置
- "submit a new post" → 预测到页面顶部
- "check the comments" → 预测到页面底部

高发平台：macos（16）、tool（15）、forum（10）

**根因分析**：
1. 长文本在不同页面布局下位置变化大
2. 动态内容（如评论列表）使模型难以定位
3. 文本在深色/复杂背景下的视觉特征提取困难

**3. OUT_OF_BOUNDS（52 个，占 17.6%）**

预测坐标完全偏离目标，甚至远离整个页面区域。

典型失败案例：
- "view my account" → 预测 [0.04, 0.19] 而真实位置在 [2401, 14]
- "goto homepage" → 预测 [0.94, 0.11] 而真实位置在 [0, 0]
- 平均误差 541.9px，中位数 313.2px

高发平台：ios（11）、gitlab（7）、tool（6）

**根因分析**：
1. 高分辨率截图（如 ios 的 1125x2436）导致模型空间感知失常
2. 页面顶部或底部的元素容易被模型"忽略"
3. 模型在极端位置（靠近 0 或 1 边界）的预测不稳定

**4. EDGE_BIAS（45 个，占 15.2%）**

预测点落在元素边缘附近（距离 bbox 边界 20px 以内），未完全命中。

典型失败案例：
- "thumb down" → 距离 bbox 仅 42.8px
- "choose size 14" → 距离 bbox 仅 36.0px
- "enter text showing in capcha" → 距离 bbox 仅 32.8px

高发平台：windows（13）、macos（13）、tool（8）

**根因分析**：
1. ShowUI 训练时使用 bbox 中心点作为目标，但模型倾向于预测到元素边缘
2. 小元素（<50px）的 bbox 容错空间小
3. 坐标回归的精度不足

**5. CENTER_BIAS（8 个，占 2.7%）**

模型倾向于预测到页面中心位置，对靠近边角的元素定位不准。

典型失败案例：
- "undo" → 预测 [0.5, 0.37] 而真实位置在 [2, 0]

1. 训练数据中页面中心区域样本占比偏多
2. 位置编码对边角区域的表示能力不足

**6. NEAR_MISS（4 个，占 1.4%）**

预测到邻近的同类元素上，如相邻的图标被混淆。

典型失败案例：
- "pin to taskbar" → 预测到相邻图标
- "adjust the volume" → 预测到相邻控制按钮

**根因分析**：
1. 密集排列的同类元素区分度不足
2. 缺乏局部上下文信息

### 12.4 改进方案实现

#### 12.4.1 方案一：坐标后处理优化（P0, 低难度, 立即实施）

**问题**：EDGE_BIAS（15.2%）和 OUT_OF_BOUNDS（17.6%）占错误总数的 32.8%，可通过后处理快速修复。

**实现方案**：

```python
class CoordinatePostProcessor:
    """坐标后处理优化器。"""
    
    def __init__(self):
        self.edge_buffer = 0.02  # 边缘缓冲比例
        self.center_bias_correction = [0.0, 0.0]  # 中心偏置校正量
        
    def process(self, raw_point, img_size):
        x, y = raw_point
        
        # 1. 边界约束：防止坐标落在页面边缘外
        x = max(self.edge_buffer, min(1.0 - self.edge_buffer, x))
        y = max(self.edge_buffer, min(1.0 - self.edge_buffer, y))
        
        # 2. 中心偏置校正
        x += self.center_bias_correction[0]
        y += self.center_bias_correction[1]
        
        # 3. 多尺度一致性校验（如果有多尺度预测结果）
        # ...
        
        return [x, y]
```

**预期收益**：+3-5%，主要修复 EDGE_BIAS 和 OUT_OF_BOUNDS 错误。

#### 12.4.2 方案二：多尺度滑动窗口推理（P1, 中等难度）

**问题**：高分辨率截图（如 ios 1125x2436）导致模型定位不稳定，OUT_OF_BOUNDS 占 17.6%。

**实现方案**：
1. 将输入截图缩放到固定分辨率（如 448x448）
2. 在多个尺度上分别推理
3. 对多尺度预测结果做加权平均
4. 结合原始分辨率做位置映射

```python
def predict_multiscale(self, image, query, scales=[0.5, 1.0, 1.5]):
    """多尺度推理，取加权平均坐标。"""
    predictions = []
    for scale in scales:
        scaled_img = resize(image, scale)
        pred = self._predict_single(scaled_img, query)
        # 映射回原始坐标空间
        pred_mapped = [pred[0] / scale, pred[1] / scale]
        predictions.append(pred_mapped)
    
    # 加权平均（排除离群点）
    valid = self._filter_outliers(predictions)
    return [sum(p[0] for p in valid) / len(valid),
            sum(p[1] for p in valid) / len(valid)]
```

**预期收益**：+2-3%，主要修复 OUT_OF_BOUNDS 和 ICON_CONFUSION。

#### 12.4.3 方案三：图标定位增强（P0, 中等难度）

**问题**：ICON_CONFUSION 占错误总数的 41.2%，是最大的优化空间。

**实现方案 A - 局部特征增强**：
对预测点周围区域做局部放大，重新推理确认：

```python
def refine_with_local_crop(self, image, initial_pred, query, crop_scale=2.0):
    """在预测点周围做局部放大，精确定位。"""
    h, w = image.shape[:2]
    cx, cy = initial_pred[0] * w, initial_pred[1] * h
    
    # 裁剪局部区域
    crop_size = int(min(w, h) / crop_scale)
    x1 = max(0, int(cx - crop_size / 2))
    y1 = max(0, int(cy - crop_size / 2))
    x2 = min(w, x1 + crop_size)
    y2 = min(h, y1 + crop_size)
    
    crop = image[y1:y2, x1:x2]
    local_pred = self._predict_single(crop, query)
    
    # 映射回全局坐标
    global_x = (x1 + local_pred[0] * (x2 - x1)) / w
    global_y = (y1 + local_pred[1] * (y2 - y1)) / h
    
    # 融合初始预测和局部预测
    return [(initial_pred[0] + global_x) / 2,
            (initial_pred[1] + global_y) / 2]
```

**实现方案 B - 图标专用 Prompt**：
针对图标类元素，使用专门的 prompt 模板：

```
# 通用 prompt（当前）：
"Based on the screenshot of the page, I give a text description 
and you give its corresponding location..."

# 图标专用 prompt（新增）：
"Based on the screenshot of the page, I give a description of an icon
and you give its precise location. Focus on finding the exact icon,
especially small icons in toolbars and menus..."
```

**预期收益**：+5-8%，主要修复 ICON_CONFUSION。

#### 12.4.4 方案四：图像预处理增强（P1, 低难度）

**问题**：图像分辨率差异大（web: 1280x720, mobile: 各种分辨率），影响定位稳定性。

**实现方案**：
1. 自适应图像缩放策略
2. 对比度增强（对低对比度图标）
3. 边缘检测辅助（对密集排列的元素）

```python
def preprocess_image(self, image_path, target_size=(448, 448)):
    """自适应图像预处理。"""
    img = Image.open(image_path)
    orig_w, orig_h = img.size
    
    # 计算缩放比例
    scale = min(target_size[0] / orig_w, target_size[1] / orig_h)
    new_w, new_h = int(orig_w * scale), int(orig_h * scale)
    
    # 保持宽高比缩放
    img_resized = img.resize((new_w, new_h), Image.LANCZOS)
    
    # 填充到目标尺寸
    padded = Image.new('RGB', target_size, (255, 255, 255))
    padded.paste(img_resized, ((target_size[0] - new_w) // 2,
                                (target_size[1] - new_h) // 2))
    
    return padded, orig_w, orig_h, scale
```

**预期收益**：+1-2%，作为其他优化方案的基础。

#### 12.4.5 方案五：集成推理策略（P2, 高难度）

**问题**：单一模型预测不稳定，对困难样本（特别是图标）缺乏鲁棒性。

**实现方案**：
1. 多个推理策略的集成投票
2. 结合 DOM 信息的交叉验证（已实现）
3. 多轮推理的置信度评估

```python
def ensemble_predict(self, image, query, num_samples=3):
    """集成推理：多次采样取最稳定结果。"""
    predictions = []
    for _ in range(num_samples):
        pred = self._predict_single(image, query)
        predictions.append(pred)
    
    # 计算预测的稳定性
    variances = [np.var([p[0] for p in predictions]),
                 np.var([p[1] for p in predictions])]
    mean_pred = [np.mean([p[0] for p in predictions]),
                 np.mean([p[1] for p in predictions])]
    
    return mean_pred, variances
```

**预期收益**：+1-3%，提高困难样本的定位稳定性。
